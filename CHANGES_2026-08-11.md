# Changes — 2026-08-11

Covers everything accumulated since the last commit (`3fc2979`, 2026-06-18), including the
CAN reliability work started 2026-06-22 (superseding the old `CHANGES22-6-2026.md` notes,
some of which described an approach that was later reverted — see §1).

## 1. CAN reliability / board-not-responding fix

**Files:** `App/Src/can_helper.c`, `Core/Src/main.c`, `STM32_code.ioc`

- **`board_id = Read_Board_ID()` moved before `HAL_FDCAN_Start`** (`main.c`) — board ID must
  be known before the CAN peripheral starts accepting traffic.
- **Added ping opcode `0x06`** (`can_helper.c`) — board replies with `[0xA1, board_id_byte]`,
  used by the Python side's `scan_boards()`/`poll_presence()` to detect which boards are
  actually on the bus.
- `STM32_code.ioc`: `FrameFormat` explicitly set to `FDCAN_FRAME_CLASSIC`.

**Reverted from the 2026-06-22 attempt** (previously documented in the now-removed
`CHANGES22-6-2026.md`): CAN FD mode and a hardware CAN filter were tried that day to cut bus
load. Both were rolled back — the hardware filter (`StdFiltersNbr` config) crashed release
builds, and FD mode was abandoned in favor of staying on classic CAN (dual 8-byte frames,
opcodes `0x01`/`0x02`). Protocol is back to what it was before that attempt, plus the
ping/pong addition above.

## 2. ADC DMA hang fix

**File:** `App/Src/motor_helper.c`

`fetch_potentiometer_values()` waited forever (`while (!conv_complete[0] || !conv_complete[1])`)
for both ADC DMA channels to finish — if either conversion-complete interrupt was ever
missed, the board hung completely, with no recovery. Confirmed live on hardware via
OpenOCD/GDB: the board hung at boot inside this loop, called 1000× in `position_init()` plus
every control cycle after.

**Fix:** bounded the wait to 2 ms (`ADC_CONV_TIMEOUT_US`). On timeout, both DMA channels are
stopped (`HAL_ADC_Stop_DMA`) and the function returns, keeping the last-known-good `pot_raw`
values instead of hanging forever. Added `adc_timeout_count` for visibility into how often
this fires.

## 3. Fleet presence tracking / robustness

**Files:** `cantest/communication.py`, `cantest/engine.py`

- `MotorCommunication` now tracks `active_boards`, populated by `scan_boards()` (full sweep,
  used at startup) and `poll_presence()` (incremental, rotates through a subset of already-
  active boards plus all currently-missing ones each call — a full 30-board sweep happens
  over several calls instead of one large burst).
- Both scan methods share an `RLock` so a background presence check and a manual scan don't
  steal each other's pong replies.
- `send_positions` skips boards known to be absent (once scanned at least once) instead of
  writing into the void every cycle.
- Throttled error/warning logging (`CAN send failed`, overbudget cycle warnings) — a
  wedged/unterminated bus used to flood stdout with one line per failed frame.
- `ControlMotor` (`engine.py`) scans on init and runs a background `_monitor_loop` thread
  that keeps re-polling presence, with exponential backoff up to 10s if the whole bus looks
  dead (distinguishes "one flaky board" from "bus is down"). Added `shutdown()` to stop it
  cleanly.

## 4. Per-board min_pwm calibration + new calibration tool

**Files:** `cantest/limits.py`, `cantest/config.py`, `cantest/main.py`,
`cantest/gui/main_window.py`, `HW_tests/calibration_app.py`

- New `HW_tests/calibration_app.py`: standalone Qt app that calibrates all boards in
  parallel — per-motor stiction search (sweeps `min_pwm` until a motor moves), optional
  safe-range sweep (`find_range`) that walks each motor outward until it physically stalls,
  and flags results as suspicious when movement direction/magnitude doesn't match what was
  commanded (helps catch phantom/misconnected channels — see calibration session notes).
  Sends the recommended config to each board as soon as it finishes. Saves results to
  `HW_tests/calibrations/<timestamp>.json` and `HW_tests/calibrations/latest.json`.
- `cantest/limits.py`: `load_min_pwm()` reads `recommended_min_pwm` per board from
  `CALIBRATION_FILE` (`HW_tests/calibrations/latest.json`), falling back to
  `DEFAULT_MIN_PWM=20` for any board missing from the file. `load_all_limits()` now returns
  `(min_limits, max_limits, min_pwm_by_board)`.
- `cantest/config.py`: added `CALIBRATION_FILE`, `DEFAULT_MIN_PWM`; `MOTOR_RANGE` 40 → 150.
- `cantest/main.py`, `cantest/gui/main_window.py`: updated for the new 3-tuple
  `load_all_limits()` return; GUI's file watcher also watches `CALIBRATION_FILE` when it
  exists (can't watch a file that doesn't exist yet — use "Reload limits" after the first
  calibration run).

**Still open:** `safe_min`/`safe_max` per-motor range data collected by `find_range` isn't
consumed anywhere yet — only `recommended_min_pwm` is read back. Wiring per-motor safe
ranges into `load_all_limits()` as a clamp (not a normalization) is the next step, needed so
the wave-generation code in `wingcontrol.py` — which sends every motor the same absolute
target value sampled from `u(x, y, t)` at its real position — clips individual motors at
their own real mechanical limit instead of exceeding it.
